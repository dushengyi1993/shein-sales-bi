# SHEIN BI / Ops 2026.07.27.1 发布说明

发布日期：2026-07-27
Git tag：`2026.07.27.1`
对比基线：`2026.07.26.2`

## 发布结论

本版修复一次历史销售店铺身份串号，并把“已落定退款”和“待决售后风险”统一成页面、利润和体检共用的业务口径。此前审查只验证了售后计算公式，没有检查销售事实、售后事实、OpenAPI 与 SKC 店铺归属的跨表一致性，因此漏掉了问题；本版把这类一致性检查加入永久门禁。

## 根因与完整影响范围

- `2026-05-14` 至 `2026-06-02`，三个浏览器销售 profile 发生循环错登：文件标记为 `QY` 的实际属于 `YJ`，`XL` 实际属于 `QY`，`YJ` 实际属于 `XL`。
- 完整影响为 `110` 条订单商品行、`109` 个订单、`95` 件有效销量、`11,261.81 SAR`。这不是金额或销量丢失，而是店铺归属错误。
- `110/110` 条受影响记录均由唯一 SKC 店铺归属确认，冲突 `0`；其中 `18` 个订单另有售后店铺证据，`10` 个订单另有 OpenAPI 店铺证据。
- 边界日已核对：`2026-05-13` 仍为正常自店数据，`2026-06-03` 已恢复正常；同期链接、库存、质量、评价等业务域没有发现相同循环错配。

## 修复方式

- 生产修复前生成确定性 manifest，并以精确 SHA-256 授权同一份事务；同步修正订单商品、订单头、支付标记、原始目录、店铺日汇总和订单复查状态。
- 所有被改写的订单商品行写入 `ops.order_store_reassignment_audit`，保留旧键、新键、原店、实际店和证据，支持逐行追责。
- 历史纠正规则进入受版本控制的 `config/historical_store_identity_corrections.json`；后续全历史重载会在入口应用同一规则，不会把错误重新导入。
- 新增五类体检错误：销售/售后跨店、订单商品与唯一 SKC 归属不一致、正式销售与 OpenAPI 店铺不一致、稳定键店铺前缀不一致、店铺日汇总与订单明细不一致。
- 链接和业务域属于同一组每日慢变快照，只彼此比较新鲜度；当天 Webhook 销售实时前进时，不再把正常的上一完整日链接快照误报为过期。

## 退货退款与净销量

- 新增 `mart.after_sales_settlement_detail` 作为唯一结算语义：
  - `退款已落定`：有明确最终退款信号，冲减净销量和已落定利润。
  - `退款待落定`：申请仍在处理，只显示风险，不提前改写净销量。
  - `已取消/关闭`：无退款闭环。
  - `不影响退款`：当前事实不足以构成退款候选。
- 退货退款页继续展示全部售后涉及金额，并在小字中拆出已落定与待决的单数、件数和金额；明细新增“退款结论”，平台原始流程状态保留为辅助信息。
- `已妥投`、退货包裹 `已签收` 不能单独证明已经退款；利润与页面不再各自维护不同的关键词判断。

## 回滚

- 源码回滚到 `2026.07.26.2` 不会自动反向改写已经纠正的事实表。
- 如确需回滚数据，必须从上述生产备份恢复或根据 `ops.order_store_reassignment_audit` 编写反向事务；不得手工只改某一张销售或售后表。
- 回滚前必须停止相关写入、另做当前数据库备份，并重新验证总量守恒和五类一致性检查。
