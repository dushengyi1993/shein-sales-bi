## 2. 首页看板筛选联动

- 首页筛选区必须放在页面最上方统一 sticky 工具栏内，不能放回经营总览卡片或 hero 下方；首页顶部工具栏内有独立筛选区：
  - 货号/SKC/品名筛选：`homeProductFilter`
  - 店铺/分组筛选：`homeStoreFilter`
- 首页顶部筛选栏在桌面宽屏下必须保持单行：货号搜索、店铺/分组、范围提示、清空按钮和时间筛选在同一行内；提示标签要给足宽度，不能互相挤压；在窄屏下才允许按响应式折行。
- 普通子页面筛选栏同样放在顶部 sticky 工具栏，但布局要比首页更克制：全局搜索和货号/SKC/品名框适中，店铺框明显短一些，时间框更长以完整显示起止日期。动作池不显示时间筛选，使用动作池专用筛选。
- 店铺筛选支持：
  - `全部店铺`
  - `DSY 组`
  - `LGM 组`
  - 16 个单店代码
- 首页顶部矩阵、日销趋势、月销趋势、店铺排行、产品排行必须同时受以下条件联动：
  - 时间段
  - 店铺或分组
  - 货号/SKC/品名
- 货号/SKC/品名筛选同时驱动首页"单货号成交价格分布"面板。
- 默认未选择店铺/货号时，顶部矩阵固定显示三行：`总计`、`DSY 组`、`LGM 组`。
- 选择某个分组时，顶部矩阵显示该分组口径。
- 选择某个单店时，顶部矩阵显示该店口径。
- 选择某个货号时，所有指标和趋势按该货号在当前店铺/分组范围内重算。
- 选择“货号 + 店铺”组合时，首页趋势和排行使用 `homeRankings/rankings.dailyStoreProducts` 的店铺×货号日粒度数据，不再只看全局货号汇总；货号筛选不得把整个首页阻塞在较慢的 `profit` section 上，利润卡可单独显示“待预热”，但销售/订单/售后和排行应继续按已加载的 `homeRankings` / `afterSales` 更新。

## 2.1 产品显示名与后台 key

- 用户可见的产品主标题统一优先读取 `product_display_name`；顶层 `DATA.productDisplayNames[standard_goods_sn]` 是页面和问数机器人共用的兜底字典。
- `product_display_name` 的语义是“标准货号 + 中文品名”，不是 SHEIN 后台长商品标题。示例：`SM-505A` 显示为 `SM-505A电动缝纫机`，`S1810电热水壶` 保持完整标准名。
- `product_display_name` 只负责展示；筛选、点击、下钻、`data-*` 属性、仓库归因和任务执行仍使用 `standard_goods_sn`。不要把显示名反写成新的归并 key。
- 没有可靠中文来源的异常短码不编造中文，保留原值并由 `product_display_name_needs_review` 标记，后续集中给用户确认。

## 3. 时间筛选规则

- 首页和需要当前时段口径的子页面共用时间筛选逻辑。
- 快捷按钮在时间按钮外侧，常用时间段不用打开弹窗：
  - 今天
  - 昨天
  - 近 3 天
  - 近 7 天
  - 近 15 天
  - 近 30 天
  - 本月
  - 上个月
  - 近 3 个月
  - 近一年
- 点击时间按钮后弹出大号双日历：
  - 左侧选择开始日期。
  - 右侧选择结束日期。
  - 上方同时保留两个 `YYYY-MM-DD` 文本日期输入框，避免浏览器原生小日历和自定义大日历叠在一起。
  - 弹窗应固定在视口内且不横向溢出；点击月份前后切换时，弹窗必须保持打开，`aria-expanded=true`，不能重渲染后重新变成 `hidden`。
  - 如果弹窗被移动到 `document.body`，日期按钮和月份切换按钮都必须在实际弹窗根节点上绑定，不能继续只在 toolbar root 上查找。
- “今天”按电脑当前自然日计算，不用仓库最新销售日冒充今天。

## 3.1 顶部全局筛选与页面局部筛选

- 页面最上方 sticky 工具栏只放真正全局有效的条件：
  - 时间段
  - 店铺 / 分组
  - 货号 / SKC / 品名
  - 全局搜索
- 顶部全局筛选会影响首页、店铺、货号 360、SKC/链接、评价/口碑、订单/售后、成本/利润、实际库存/去化等需要当前时间范围的页面。
- `今日动作池` 是当前最新待办池，不按时间段回看；动作池页不显示时间选择窗口，也不把 `startDate/endDate/rangePreset` 写入当前动作池视图链接。
- `业务域`、`风险`、`处理状态`、`快速聚焦` 只属于 `今日动作池`，必须放在动作池页面顶部 sticky 工具栏里的“动作池专用筛选”区域。
- 动作池专用筛选只影响动作池，不得影响评价、订单/售后、店铺、货号或 SKC/链接页面。
- URL hash 里即使残留 `domain/risk/status/focus`，非动作池页面也必须忽略这些条件，避免出现隐形筛选导致“数据消失”。

## 4. 首页顶部矩阵

顶部矩阵统一为四张卡：

1. 当前时段销售额：范围 × SAR / RMB。
2. 当前时段订单 / 销量 / 动销：范围 × 订单 / 销量 / 动销货号数。
3. 当前时段退货 / 售后：范围 × 数量 / 金额，金额同时显示 SAR 和按 `1 SAR = 1.8 RMB` 估算的 RMB。
4. 当前时段真实利润：范围 × SAR / RMB。真实利润来自成本表、退货保守口径和仓储费口径；成本未覆盖时显示“待成本表 / 成本覆盖率”，不得继续用 `25%` 粗估冒充真实利润。首页轻量利润数据来自服务端 `homeProfit` section，它从当前 `profit` section cache 派生；若 `staleSource=true` 或 `sourceGeneratedAt` 旧于当前 `data.json.__sections.generatedAt`，页面数字只能视为旧缓存，不可当业务真实利润。

首页销售/订单/售后和排行首屏不得拉完整 `rankings`；应优先拉 `homeRankings`。`homeRankings` 只保留首页聚合必需字段，商品显示名通过 `productDisplayNames` 字典解析，重复长 `goods_title` / `skc_list` 不应进入首页首屏 payload。

首页、趋势和排行里的成交额默认统一为“已落定净成交额”：只有平台已经明确 `同意退款`，或有等价最终退款信号的售后才冲减净成交额、订单数和净销量。`待买家退货`、`待交接`、`待卖家处理`、`待买家选择方案`、`已妥投但尚未确认退款` 等未落定状态只进入“待决售后风险”，不得提前伪装成真实退款；后续落定或取消时再自动转入对应口径。利润仍保留这些待决申请的风险调整参考值。只有已落定且确有退货包裹、又缺实际费用的退货退款才可使用 `13.88 SAR` 包裹估算；仅退款、派件失败或派件异常不重复扣退货派送费。

视觉规则：

- 数字居中。
- 数字字号必须明显大于辅助文字。
- 默认三行顺序固定为：总计、DSY 组、LGM 组。
- 筛选到单店或分组后，不要继续强行展示不相关的三行。

## 5. 趋势图

- 日销趋势和月销趋势上下排列，各占满全宽；图表绘图区要尽量贴近卡片左右边界，避免出现大块空白。
- 趋势图不能通过 `preserveAspectRatio=none` 或类似方式强行横向拉伸；应通过扩大自然 SVG 画布、合理压缩内边距和保留坐标轴可读区域来解决宽度问题。
- 月利润趋势也放在首页趋势区，默认近 6 个月。
- 未选择店铺/货号时，折线包含三条：总计、DSY、LGM。
- 选择店铺、分组、货号或组合后，折线切换为当前筛选范围。
- 日销趋势默认展示最近 30 天。
- 月销趋势默认展示过去 6 个月。
- 当用户选择非单日时间段时，趋势图随选择的起止时间段变化。
- 纵轴使用整数刻度，不显示小数。
- 图上只标关键节点，避免过密。
- 鼠标悬停某个日期/月时，显示完整 SAR 数值，不使用 K/M 缩写。
- 月利润趋势、单店和货号筛选均展示含仓储真实利润。仓储费按货号证据、货号 × 店铺销量、`CENTRAL_POOL` 的顺序分配并对账；无法证明归属的余额保留在 `CENTRAL_POOL`，不按净销售额或体积推算填补。

### 单货号成交价格分布

- 仅在选中货号/SKC/品名筛选后显示；位于首页趋势图下方。
- 数据来源：当前销售明细行，按行计算均价 = 净销售额 / 净销量。
- 自动分桶，高亮销量最高的价格区间（热力区间）。
- KPI：均价、热力区间、价格范围、总销量、订单数。
- 用途：活动定价前判断真实成交价格分布，避免盲目按标价或历史均价报活动。

### 成交价散点图（priceScatter）

- 位于首页趋势区下方，"单货号成交价格分布"面板之后。
- 横轴为订单日期，纵轴为成交单价（SAR），每个订单明细行作为一个散点。
- 数据来源：`fact.order_item`，`unit_price_sar = sales_sar / quantity`。
- 不筛选货号时显示全货盘成交价分布；筛选货号/SKC/品名后缩小到该货号范围。
- 支持时间范围筛选（今天/昨天/近七天/本月/全部）。
- Section API：`/api/bi/section/priceScatter`。
- 用途：通过点位分布和密度判断哪个价格最好卖，为报活动打折提供指导。

## 6. 排行榜

- 店铺排行默认显示完整 19 店；被筛到分组或货号时，显示当前范围内的完整店铺排行。
- 店铺标签只显示 `DL / DX / HL` 这类店铺代码，不重复写 `DSY / LGM` 前缀。
- 产品排行按标准货号归并，不按店铺后台原始货号拆散。
- 首页“店铺净成交额排行”和“产品净成交额排行”必须显示选定周期成交均价，口径为当前筛选范围内 `净成交额 / 净销量`，展示为 `SAR/件`；净销量为 0 时显示空值，不用订单均价或历史均价替代。
- `CM-121E美式咖啡机`、`121E美式咖啡机`、`121E`、`CM121E`、`CM-121E` 是同一个 121E 咖啡机标准货号，必须统一归并到 `CM-121E美式咖啡机`；否则 TZ 等店会在货号 360、首页筛选和库存决策里被拆成单独货号。
- 产品排行显示 `product_display_name`，不显示 SHEIN 后台长商品标题，避免标题过长、不同店标题不一致、行高错位。
- 点击店铺排行进入店铺视角。
- 点击产品排行进入货号 360。

## 7. 子页面降噪规则

- 每个子页面顶部要有统一的页面说明卡，说明这个页面回答什么问题、先看哪里、再看哪里、最后怎么下钻。
- 每个子页面说明卡下方要有“本页决策摘要”，用 4 张指标卡先给出当前焦点、风险、动作数量和下一步建议。
- 子页面不要一进来就只堆表格；长明细默认放进复核明细或折叠区。
- 店铺视角重点回答“这个店要先处理什么”。
- 货号 360 回答“这个标准货号该扩、该修还是该淘汰”。
- SKC/链接回答“这条链接该优化、替换、补资料还是不动”。
- 评价/口碑回答“差评、低星和质量投诉集中在哪个货号、店铺、SKC”。
- 订单/售后回答“销售、退货、履约、财务能不能互相印证”。
- 成本/利润回答“真实利润来自哪里，哪些货号值得加码，哪些货号利润差，以及选品前如何估算利润率”。
- 实际库存/去化回答“ET 实盘还剩多少、在途能否接上、哪些货号快断货或库存沉淀”。库存主证据来自 ET 货代仓实盘、发货申请单、箱明细和出库/库存流水；SHEIN 后台库存只是各店链接的虚拟前台库存，只用于“店铺 × 标准货号已上架库存矩阵”等链接库存展示。
- 今日动作池回答“今天先处理什么”，口径是当前最新待办池，不随时间筛选回看历史。
- 今日动作池同一店铺、同一 SKC、同一业务域的多条规则命中要合并为一张动作卡，显示“合并 N 条”和每条规则信号，避免同一链接重复处理；跨业务域动作仍保留独立卡片。
- 订单/售后和今日动作池如果被筛选为空，但底库仍有数据，必须显示可读提示；订单/售后只提示顶部全局筛选或时间段，动作池则同时提示本页专用筛选。
- 系统状态回答“今天的数据能不能放心看”。
- 系统状态允许区分“历史自动任务失败但已恢复”和“当前数据不可用”：`2026-05-09 04:20` ET 同源探测问题已修复并复验，`2026-05-09 05:30` / `07:00` 已正式自动跑通后，不应继续把早期 Docker/WSL 或 ET 登录恢复态显示为当前待验证。

## 8. 店铺视角当前规则

- 选中单店后，不再显示全局“销售最高店 / 风险最高店”，避免误认为本店结论。
- 店铺页时间筛选放在顶部筛选区，当前时段销售、订单、销量、动销、售后申请数都跟随时间段变化。
- `风险分` 是店铺综合优先级分，用来排序“先看哪个店”，不是销售额或金额。
- `动作分` 是单条动作的优先级分，用来排序“先处理哪条动作”，不是金额或销量。
- `在途单 / 在途收入` 来自财务收入明细最新快照，主要用于回款和对账复核。
- 同货号重复链接对比必须展示同组全部 SKC，并给出当前最佳、弱于最佳、淘汰候选、可果断下架、先推替代等清晰判断。
- 链接指标统一按 `曝光 -> 访客 -> 销量 -> 支付率` 展示，并在每个指标下显示 `7 天 / 30 天` 二级表头。
- 下架/淘汰候选统一使用安全口径：已上架、近 7 天曝光 `c7EpsUv <= 300`、近 7 天销量 `c7_sale_cnt = 0`、SHEIN 新品标签 `newGoodsTag` 为空，且首次上架已满 15 天。售罄/下架后恢复在售的老链接还必须满足“最近库存恢复/重新在售已满 15 天”：优先读取每日库存 `0 -> 正数` 的恢复日期，其次读取最近 60 天链接状态跃迁；OpenAPI `last_shelf_time` 只能作兜底，因为补库存恢复后它可能不更新。首次上架未满 15 天、最近恢复未满 15 天、缺首次上架时间、缺新品标签字段或恢复证据链不完整的链接不得进入可执行下架候选；刚成功的恢复期营销活动是保护佐证，不是下架理由。页面只能先出明细给用户确认。
- 下架候选输出为 CSV/JSON/Markdown 报告，不直接在门户 UI 执行下架；用户确认后走云端受控执行器。
- 已下架但货号未改成`（废）...`的链接可用 `repair_retire_supplier_code_openapi.mjs` 单独修复，不影响已完成的下架状态。
- 本店低展示库存预警来自 `fact.visible_inventory_snapshot` 最新正确展示库存快照，不使用备货信息里的虚假库存。

## 10. 成本 / 利润当前规则

- 成本/利润页独立为一个子页面，不塞进订单/售后页。
- 首页“真实利润”和成本/利润页都随顶部时间、店铺/分组、货号/SKC 筛选联动。

- 成本/利润页下方的月度利润明细、高利润/低利润货号、成本覆盖缺口，也必须跟随同一套筛选；只有“历史样本：体积 × 利润率”可使用成本表全量样本，并在页面文案中明确这是选品样本而不是当前销售利润表。
- 高利润 / 低利润货号分界线固定为 `20%` 利润率：`>= 20%` 为高利润 / 可加码，`< 20%` 为低利润 / 需要处理。
- 利润页必须分开显示“已落定利润”和“未落定售后风险”，不得把未结售后直接伪装成已落定损益。已落定利润使用已结算/已确认事实；未结售后风险另列保守影响和风险调整后参考值。
- 退货费优先使用财务核对单已结算净成本，其次使用退货单商品行 `performancePrice` 实际费用；仅在实际值都缺失且确为退货包裹时，才用 `13.88 SAR` 估算，并明确标记为估算，不能把仅退款、派件失败或零金额取消单套入该费用。
- 同货号成本由期初与后续入库事件的移动加权平均台账形成；期初只可取生效日前一日的 ET 结存，会计期间冻结后不得重写。
- 发货批次缺“头程运输费金额”时，只保留为缺口，不纳入单位成本均摊，避免成本被低估。
- 仓储费来自 ET 物流仓服账单 `仓储费`：先按货号证据分配，再按货号 × 店铺销量分配，仍无法归属的余额进入 `CENTRAL_POOL`；各层均须可回到 ET 日总账。不得把全量仓储费直接以店铺净销售额作为主路径。
- `TS`、`MZ` 开店以来都归 `DSY` 组。
- 成本覆盖不足时页面必须显示覆盖率和缺成本销售额，不允许用预测利润填补空白。

## 10.1 实际库存 / 去化页面口径

- 实际库存/去化页独立为一个子页面，不塞进成本/利润或订单/售后页。
- 页面顶部回答：ET 当前总库存、ET 可售库存、ET 在途/待入仓、加权去化速度、去化周期和仓储成本。
- 库存主口径以 ET 实盘为准：运营可售默认只取 `09` 散件，唯 `SK-03038` 例外取 `09+01`；全仓物理量（09/01/03_RTV/04/06 等）单列，不等同运营可售。未匹配或过期为 `unknown`，不可显示为 0 或由成本表推算。
- SHEIN 后台库存是虚拟前台库存，只用于查看某店已上架链接还填了多少库存；除“店铺 × 标准货号已上架库存矩阵”外，不把 SHEIN 库存当总库存或供应量。
- 去化速度使用销量数据，公式为近 7 天日均 × 30% + 近 30 天日均 × 70%；页面将其年化到 30 天展示为“预计月销”，并同时展示近 30 天实际销量。近 30 天不足 5 件时标记低样本。已断货货号不能同时标“完全卖不动”，标签逻辑要先判断库存状态再判断滞销。
- 店铺/分组筛选只影响销售速度、风险排序和链接库存矩阵，不硬拆 ET 物理库存；物理库存保持全局货号口径。

- 选品计算器用于模拟售价、采购价、头程、其它成本、退货率和体积对利润率的影响；体积只做选品参考，不直接扣单品仓储费。

- 选品模块当前升级为“选品标尺模型”：用真实历史利润校准 `进货价 × 倒推体积` 矩阵，再提供新选品保本售价和 25% 利润率售价试算。当前成本表没有物理长宽高，体积由历史头程按约 `1600 RMB/方` 倒推；新选品未来头程按 `2000 RMB/方` 重算。

## 10.2 营销中心当前规则

- 营销中心回答“已上架链接有没有进入普通营销活动、限时折扣和优惠券三层营销覆盖”，不是营销活动执行器，也不替代报名脚本的 live 回读。
- 顶部 KPI 的分母只看当前已上架链接；普通营销活动和限时折扣覆盖来自 `linksData` 下发的活动名、状态、生效时间和价格线索。
- 优惠券覆盖使用严格口径：`coupon_factor=1` / `marketing_coupon_factor=1` 代表无券，不得计入“报优惠券”；只有明确券档、券活动 ID 或有效券摘要的链接才计入优惠券覆盖。页面文案必须避免出现“1%券”或“已报名/待确认”这类误导表达。
- 平台新品标签（`新款`/`新品`/`New Arrivals`/`new arrival`）在超出 7 天窗口后仍可保持新品/前五力度待遇，除非该链接已有普通营销活动。配置在 `config/marketing_pricing_policy.json` 的 `newListingWithin7Days.platformNewLabelPatterns`。
- “营销覆盖台账”按链接逐行展示普通活动、限时折扣、优惠券三类卡片，必须显示活动名、报名/覆盖状态、生效时间、活动价 / 折扣率 / 券信息；缺报名只用胶囊标记在同一行，不再另起一个冗长候选池。
- 台账必须有分页和每页条数选择；全局店铺 / 负责人 / 货号搜索会联动营销中心，并在筛选变化时回到第 1 页。
- “待报名活动清单”只展示还在报名期或尚未报完的活动名、类型、报名时间、生效时间和入选链接数；它来自 `actions` / 候选线索，不等于已报名成功，也不能当作最终报名完成证据。
- 活动表现如果没有稳定字段，页面只能显示“待接入表现”；不能用报名状态、价格线索或候选池数据伪造成活动表现。

- 利润页当前结构固定为：先看结论 → 月利润趋势 → 高利润/低利润货号 → 选品标尺/利润试算 → 成本覆盖缺口。
- 顶部“先看结论”必须直接告诉用户当前筛选范围是否赚钱，并显示净成交、商品成本、反转订单和仓储口径。

## 14. 订单 / 售后复核台

- 订单 / 售后页不是订单流水页，而是经营复核台，核心回答三件事：成交是否真实、售后压力来自哪里、哪些订单/货号需要复核。
- 页面主区先显示“这页先看什么”、订单销售、售后金额、财务待结算、履约异常/取消和优先复核对象。
- 退货退款顶部保留售后涉及总额，小字只额外提示“退款待落定”的单数和金额；已落定结果由总量、净量和明细表达，避免摘要文案过长。明细中的“退款结论”必须使用同一套结构化结算状态。平台原始流程状态继续以小字保留，但 `已妥投`、`已签收` 本身不能被解释成已经退款。
- 已落定退款会冲减净销量和已落定利润；待决售后只作为风险提示，不提前冲减净销量。页面、利润 mart 和数据体检必须共用 `mart.after_sales_settlement_detail`，禁止各自维护另一套关键词判断。
- 首页退货卡的“待落定金额”与利润卡的“待决售后风险”使用同一个标准化风险金额：同一申请在多个平台流程状态下重复出现时不重复计款，金额超过订单成交额时按实际可受影响收入封顶。
- “RTV入仓测算”以风险调整后利润为基线，再加回已确认入仓可二售的商品成本；不再从已落定利润直接加回，以免遗漏待决售后风险。
- 首页订单/销量卡直接并列总销量与净销量，不再额外重复计算公式；首页退货/售后卡和退货退款页的小字只强调“退款待落定”，完整已落定/待落定拆分仍保留在状态筛选、时间分析和售后明细中。
- 财务店铺摘要、营销活动、在途订单、商品/SKC、订单明细、售后明细、履约明细都放到下方折叠证据区，需要查单时再展开。
- 优先复核对象按售后金额聚合到货号和店铺，点击可带筛选跳转，避免用户一进页面就面对多张长表。
- 订单明细必须按订单创建时间跟随顶部时间段；售后明细必须按售后申请时间跟随顶部时间段；履约明细按揽收/打印/快照时间跟随顶部时间段；财务订单/SKC 明细按财务订单发货日跟随顶部时间段。
- 财务店铺摘要是最新财务快照，只用于看待结算、在途和账期，不冒充历史月份数据；如果和当前筛选时间段不同，页面文案必须明确标注“最新快照”。

## 2026-05-17 链接管理中台基座

- BI Portal 已新增“链接管理中台”入口，定位是自动运营驾驶舱的第一层：先收集和展示待确认动作，不直接改 SHEIN 后台。
- 当前已上线能力：自然语言运营指令提交、服务端任务记录 API `/api/link-ops-tasks`、任务状态/备注/负责人/IP/UA 留痕，以及任务卡片下方基于现有链接/覆盖矩阵的店铺级建议。
- 当前建议来源仍是 BI 已有数据：店铺×货号覆盖、链接表现、同款最佳链接、缺链接/弱链接线索；它不是最终执行器。
- 当前只读链路不再调用 `/api/ops-agent/ask`、飞书问数或另一个模型。Partner CLI 的 `query` 通过 `/api/bi/query-data` 在登录账号读权限内确定性装载云端 section，返回 `aiInvoked=false` 的结构化数据，再由当前 Codex 直接筛选和计算；旧 `ask` 仅为 `query` 兼容别名。网页会话和 `chat` 保留给受控运营动作或产品路由测试，其回复不是经营事实源。
- 链接管理中台采用“会话即任务工作台”：左侧会话列表和推荐指令，中间连续对话，右侧只展示当前会话的任务目标、执行对象、材料缺口、执行方式、数据依据和操作记录。下架、换图、改标题、补链、报活动、限时折扣等明确动作必须进入任务状态机和预检；普通只读问题不得为了方便而创建任务、转问另一个 AI 或回退浏览器抓数。
- 本机素材边界：云端 BI 不能直接读取用户本机的标题文件、商品图或本机 skill。执行路径是先把图片/标题/规则上传或同步到云端会话 / 任务素材包，再由云端执行器调用 SHEIN API/WebAPI/headless 执行；缺素材、缺接口字段或缺权限时任务停在执行准备，不静默写 SHEIN。
- 素材与执行器基座：`/api/link-ops-assets` 支持把图片、PDF 证书、TXT/CSV/JSON/表格标题或规则文件上传到当前会话资料；如果当前会话已有处理事项，再同步给当前任务。本机批量同步可用 `scripts/upload_link_ops_assets.mjs`。`/api/link-ops-execute` 负责受控执行前检查、执行器调度和审计回写；不会把未执行的写操作显示为成功。
- 上新/换图的图片体验目标：用户上传图片后，聊天区展示已上传文件和 AI 图片排序建议，默认按轮播主图 1 张、细节图最多 11 张、方形图 1 张、SKU 图 / 色块图 1 张组织。用户可继续用自然语言调换顺序、剔除图片或指定用途；后台必须先把图片转换为 SHEIN 可接受的图片 URL 与发布 / `partialEdit` 图片字段，缺字段时只提示缺口。AI 只能辅助识别图片内容、质量和顺序，不能凭图片发明商品参数、认证或功能。
- 2026-05-18 补充：链接管理中台会区分“店铺已有 OpenAPI 授权”和“具体写适配器 / payload 是否可执行”。HL 已有 OpenAPI 授权和只读/销售对账能力，相关补链/复制上品命令会进入任务池与 HL API 执行准备；若具体写适配器或发布 payload 不完整，执行器会在预检阶段阻断真实提交，不得笼统回复“HL 没有权限”或谎称已提交审核。
- 2026-05-19 补充：HL 商品写执行器已接入 `/api/link-ops-execute`。对 HL 的 `copy_product_draft` 任务，服务端会调用 `scripts/link_ops_hl_openapi_executor.mjs` 做真实 OpenAPI 发品权限、站点、品牌、仓库和发布 payload 预检，并把结果写回任务 `execution.hlOpenApiExecutor`。默认调用只做 dry-run，不会提交 SHEIN；真实 `publishOrEdit` 仍需要 payload 完整和显式执行确认。若任务里没有上传 `openapiPublishPayload`，执行器会先尝试用源店 + 源 SKC 从 WebAPI 快照生成 `canonical product draft` 和发布 payload 草稿；生成结果仍缺字段时，任务应显示“缺类目属性 / SKU 尺寸重量 / supplier_sku / cost_info”等具体阻断，而不是显示“没有权限”。单独排查脚本为 `scripts/link_ops_build_product_draft_from_webapi.mjs`。
