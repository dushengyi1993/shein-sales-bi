## 2026.07.26.2：全项目审查修复

发布日期：2026-07-26

对比基线：`2026.07.26.1`

### 发布结论

本版不是只做代码整理，而是按订单、售后、退货费、RTV、移动加权成本、仓储费、实时销售、利润缓存、商品对账、营销巡检、调度和前端解释逐条复核业务链。修复原则是：正式数据守恒、历史估算明确标识、实时销售不等于虚构实时利润、失败不覆盖上一份完整证据、告警必须说清影响和下一步。

### 账务与经营口径

- 同一订单行的多笔已落定/待决售后全部进入计算；已落定优先，待决只占剩余营收和数量，整行冲销不超过原订单。
- 实际退货费按包裹归集并分摊；包裹一旦取得可信实际费用，整包不再叠加 `13.88 SAR` 估算，解决“一行实际、另一行又估算”的重复扣费。
- OpenAPI/ET 直连和手工映射命中同一 RTV 经济事件时只回仓一次，优先强证据路径，避免移动加权成本被重复入库。
- 数量为 `0` 的取消订单行不再获得 RTV 回仓数量或可二售成本；生产深度回读发现并清零了 8 条此类历史测算行。
- 移动加权台账绑定来源快照与截止时点，切点前继续明确标记 `legacy_pre_cutover_estimate`；不把无法证明批次归属的旧历史包装成精确批次成本。
- 仓储费按账单日、货号、店铺逐级分摊并保留 `CENTRAL_POOL` 余额；刷新前后执行金额守恒检查。

### 实时链路、缓存与前端

- 当天销售直接读取正式订单事实；订单 Webhook 通过 PostgreSQL `NOTIFY` + SSE 立即刷新页面，不再每 60 秒轮询。
- 订单/退货事件按 45 秒合并后自动重建成本台账和利润 cache，成功后再次推送；失败 5 分钟后重试，Portal 重启后会追赶离线事件。
- 销售已到而会计 cache 尚未覆盖时返回 `accountingPending=true`，页面明确显示“利润正自动补成本”；禁止以静态成本、旧利润或假零值代替。
- 已存在订单行若金额或数量发生变化，也先按正式订单事实更新实时销售并进入 `accountingPending`；相同内容的幂等重放不会制造假待办。
- core、section、营销快照和商品对账报告改为临时文件写入、`fsync`、原子替换；失败保留上一份完整可读证据并写真实错误元数据。
- 修复首次异步 cache 未完成时返回空结果、上传区错误抢焦点、弱对比度和状态文案难懂等前端问题。

### 调度、安全与可观测性

- 凌晨会话检查、数据库备份和昨日最终核对保持独立 timer，以共享锁做运行期互斥；修正软依赖和备份超时预算，避免 timer 叠床架屋或无意互相触发。
- 商品对账只对详情缺失、库存缺失和无 Webhook 证据的真实状态回退告警；合法非上架、OpenAPI-only 和浏览器四态差异保留为诊断。
- 营销快照即使本轮合法为空也可更新；失败/残缺结果不能覆盖上一份可信扫描，watchdog 继续保留真实历史 warning。
- GitHub Actions 固定到 commit SHA，并由 Dependabot 跟踪 action 更新；systemd 凭据落盘、锁权限和服务沙箱加入静态契约。

## 2026.07.26.1

发布日期：2026-07-26
Git tag：`2026.07.26.1`
对比基线：`2026.07.23.1`

## 发布结论

本版收口半托 Webhook 实时销售、19 店单应用 OpenAPI 数据面、BI 实时刷新与体检解释，并补齐营销限时折扣队列的可恢复执行和严格授权证据。GitHub Release 是源码基线；除本文明确列出的既有生产验收外，不把“代码已发布”写成“新营销代码已部署”。

## 主要变化

### OpenAPI 与 Webhook

- 半托生产 OpenAPI 数据面统一为 DL 单一 App 下的 19 店唯一 OpenKey；原 18 App 只作回滚资产，命中旧 App 的回调在读取正文、落库和业务处理前确认并丢弃。
- 13 类半托经营 Webhook 继续由统一 App 承载；视频转换事件保持关闭。订单、退货、商品生命周期、额度、授权、合规、物流单和 RRP 事件按业务价值分级，普通成功事件不再污染飞书或重点动态。
- 修复“待上架被误判下架”、商品上下文缺失、1970 占位时间、审核失败信息过少和多 SKC 合并丢失等问题。

### 销售、利润与数据体检

- 2026-07-23 起当天销售继续由 Webhook 触发按单 OpenAPI 写正式事实；在线 Portal 通过 PostgreSQL `NOTIFY` + SSE 增量刷新。
- 修复切源后 WebAPI/OpenAPI 双份商品行导致的销售翻倍，以及页面初次加载与实时 hydration 竞争导致的金额来回跳动。
- `03:00` WebAPI 只保留独立核对证据；19/19 店 OpenAPI 深度匹配后才原子晋升最终日切片。
- 数据体检区展示具体原因、影响和下一步；事件驱动当天合法零销量不再误报为缺抓数。

### 营销自动化

- 新增高点击低转化专属限时折扣：仅处理当前在售、近 7 天曝光人数 `>3000`、点击率 `>4%` 且销量明确为 `0` 的链接；缺失销量不按零。
- 专属价按同标准货号全局曝光 Top5 商品成本利润率再降低 2 个百分点，仍守住 15% 利润率底线；活动库存 10、周期 7 天。执行前先登记特殊价保护，再 dry-run、真实写和逐条 live 回读。
- 修复有界队列的部分成功恢复：已创建并精确覆盖的键不会因组级失败而重放；平台/ET 终态阻断与可重试错误分开处理。
- 未售库存的仓储费可按 ET 货号总费与当前实盘数量形成共享单位仓储成本，避免“所有店都没卖所以无人承担、定价误读为零仓储费”。
- 平台库存覆盖量同时考虑锁定量和“总库存减可用库存”的不可用量，不再低估补量。
- 普通活动批量提交工具新增不可变批准清单：批准原话、来源、文件 SHA-256、selection/price payload hash 和 work fingerprint 必须一致；任一文件在授权后变化即失败关闭，resume 只接受同一 fingerprint 的成功证据。

### 链接与店铺规则

- 同货号替代发布支持 live 证据确认的终态“审核拒绝”与“主动撤回”，活跃/非终态链接仍阻断重复发布。
- 修正 19 店默认视觉风格与标题组映射，并继续由 Partner CLI 回归锁定。
- 浏览器启动器支持显式端口和按需本地网络资源开关；定时孤儿清理仍只在 `03:45/09:50/21:00` 运行，不恢复每 30 分钟或每小时全局清理。

## 安全边界

- 普通营销活动、优惠券、补预算仍需当前任务明确授权。
- 负责人长期营销授权只覆盖策略白名单中的限时折扣动作。用户无需逐次提供 hash，但系统每轮必须自动计算、锁定并校验精确 payload/work hash。
- SHEIN 真实写继续要求身份、实时证据、预检、受控执行、审计和写后回读；Webhook 永不直接调用 SHEIN 写接口。
- 本 Release 不包含 OpenAPI secret、OpenKey、Cookie、账号密码、浏览器 profile、数据库 dump 或云端 `.local` 运行态。
