## 发布结论

本版把 2026-07-28 普通营销活动执行中形成的临时修复整理成可测试、可追溯、可回滚的正式源码，并同步清理当前文档中的旧 `ask`/问数机器人口径。发布本身不创建、修改或删除 SHEIN 活动。

## 普通营销活动

- 用户批准价继续作为审计基准；报名页普通档/VIP 档强制更低价格时，精确命中平台档位即可提交，并记录批准价、平台价、差额和 `below_target_due_to_platform_forced_discount`，不再重复索要确认。
- 平台档位证据按 `店铺 + SKC + 活动 ID + 有效窗口` 隔离。订单成交价审计优先使用已提交填报证据，历史缺失项使用 `config/marketing_ordinary_platform_tier_overrides.json`；其它活动的档位不得串入。
- 2026-07-28 的活动 `49283 / 49286 / 50003` 最终基线为 19 店 `743` 行：主计划 `720` 行，加用户明确批准的“仅因含仓储成本利润率低于 15% 被剔除”补充计划 `23` 行。最终回读要求缺失、错价、计划外可报、活动列表缺口和坏包全部为 0。
- 补充计划生成器只接受精确的含仓储利润率剔除原因，并要求成本、仓储、价格和利润率证据齐全；主计划和补充计划合并后，回读器重新校验完整计划键、逐行目标价和 work fingerprint，不能用实际回读行数覆盖计划行数。

## 证据与巡检

- 新品普通活动确认表必须使用生成日期不早于报告日的 `linksData`，并同时读取覆盖活动报告 `selectedStores` 全范围的原始链接快照。原始快照只补上架时间和状态，不覆盖 BI 曝光指标。
- 曝光索引新增正向指标行数和实际排名行数；存在原始链接但没有正向曝光时 fail closed，不再把“有链接行”误判为“有 Top5 证据”。
- 日报兼容新旧限时折扣修复结果，能区分已执行子集与平台/库存阻断子集；历史漂移修复证据可缓解修复前订单，但未来日期证据不会提前生效。
- 营销中心微前端出现 `LOADING_SOURCE_CODE`、`Failed to load script` 或“渲染异常”时，启动器优先定位 `/mbrs/` 页面，绕缓存重载并最多重试 3 次；仍失败才形成 blocker。

## 链接运营
