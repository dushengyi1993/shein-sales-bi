# 首次虚拟库存建仓与精确回读修复

目标版本：`2026.08.02.6`
发布日期：2026-08-02

## 问题

LQ `SK-YM-7032绞肉机 / sv260604212069776481244 / I2mpziyidk096h` 在 ET 有 18 个可售库存，但该新 SKU 尚未建立 VI 库存行。自动执行请求没有携带 `warehouseCode`，SHEIN 外层返回 `code=0`、业务层返回 `success=false`；用户在半托后台手工选择仓库后成功把 VI 可用库存改为 18。

实时复核确认：

- LQ 只有一个沙特商家仓：`PS7366747353`；
- 手工操作后 VI 库存行为 `18`，仓库编码即 `PS7366747353`；
- 原先把 PI 枚举机械解释为“SHEIN 仓实物库存”的业务结论错误，已撤回。

## 修复

- 每日库存执行器遇到缺失 VI 库存行时，先查询商家仓库列表；唯一仓或站点国家唯一匹配仓时带 `warehouseCode` 初始化库存，多仓歧义失败关闭。
- 单条维护执行器的库存 payload 始终纳入唯一 `warehouseCode`，因此 dry-run hash 与真实提交锁定同一仓库。
- 单条维护回读参数从错误的 `skuCodes` 修正为官方 `skuCodeList + warehouseType=2 + invType=VI`。
- 回读不再只判断接口 `code=0`，而是逐 SKU 校验库存行存在且实时可用库存精确等于批准目标。

## 验证

- 仓库选择专项：唯一仓、站点国家唯一匹配、多仓歧义三类用例。
- 单条维护执行器 fake OpenAPI 全流程通过，并验证 payload 带仓库编码及精确库存回读。
- BI 聊天维护 fake OpenAPI 全流程通过，库存任务生命周期收口为 `submitted_readback_matched`。
- 完整测试、CI、云端测试和发布源状态检查必须全部通过后部署。

回滚点为 `2026.08.02.5`。本次发布不执行任何新的 SHEIN 库存修改；LQ 目标库存已经由用户手工改为 18。
