# 实施路线与当前阶段

> 2026-05-16 更新：本地局域网试用和 GitHub 托管已完成；本地 BI 已封存，云端 BI `http://43.165.167.135/` 是正式入口。销售、ET、飞书日报、异常通知、RTV 完整复核、链接/业务域日更和 HL OpenAPI 双跑均已有云端 systemd 入口；下面早期阶段保留为路线回顾。

## 已完成主线

### M1-M2：方案与项目骨架

- 建立工作区目录、配置文件、脚本入口、数据模型文档和项目专用 skill。
- 明确统计口径：北京时间、订单创建时间、`1 SAR = 1.8 RMB`、预测利润率 `25%`。

### M3：店铺级销售抓取与事实表

- 完成 DSY 10 店和 LGM 6 店接入。
- 每店使用工作区内独立 Chrome profile。
- `店铺日报事实` 按 `YYYY-MM-DD__店铺代号` 幂等写入。
- 遇到 SHEIN `20302 子系统登录重定向` 时，自动恢复登录后重新抓取；失败则明确提示人工登录。

### M4：月度日销与调度

- 月表由 `店铺日报事实` 重算生成。
- 只保留当月和上个月的独立月表，更早月份进入年度汇总。
- 当前云端 systemd 调度：
  - `shein-bi-cloud-today.timer` 每两小时刷新当天销售、入仓并生成 BI Portal；
  - `shein-bi-cloud-yesterday.timer` 每天 `00:10` 刷新前一天最终销售并复核稳定日；
  - `shein-bi-db-backup.timer` 每天 `02:30` 备份数据库；
  - 本地 Windows 计划任务已封存禁用，只作回滚/迁移参考。

### M5：产品销量体系

- 产品统计已经覆盖 16 店。
- 货号通过 `config/product_aliases.json` 和 `lib/product_sku_normalizer.mjs` 归并。
- 周销/月销只保留宽表展示：`产品周销量-宽表`、`产品月销量-宽表`。

### M6：飞书日报与主看板

- 当前正式看板包括当月主看板 `SHEIN经营看板 v3-主看板` 和上月看板 `SHEIN经营看板 v3-上月`。
- 当月主看板读取 `看板数据-MAIN-*` 聚合表，上月看板读取 `看板数据-PREV-*` 聚合表；二者都不直接读取大明细表，也不依赖 Dashboard filter。
- 顶部统计卡使用 `KPI*` 专用字段，避免 `全部 + DSY + LGM` 重复求和。
- 顶部 `数据时间说明` 是飞书内部 `RICH_TEXT`，已存在块不能用公开 Dashboard 更新接口改 `data_config.text`；当前脚本通过已登录飞书网页 profile 调用内部富文本保存链路更新时间，并对页面关闭/超时等临时错误做轻量重试。
- 看板和日报图已统一颜色规范：全部/合计为绿色系，`DSY` 为蓝色系，`LGM` 为橙色系，产品榜为紫粉系；店铺排行标签只显示排名和店铺代号。
- 日报为文字 + 竖版长图，包含数据抓取时间。
- 临时复盘或重发今日战报时，可用 `scripts/generate_today_detailed_report_image.mjs` 生成只含今日数据的详尽日报图。

### M7-M9：历史回补、LGM 接入、订单/SKC 底座

- DSY 与 LGM 历史日销和产品统计已回补。
- 已沉淀订单级和订单商品/SKC 级明细底座，供后续退货、成本利润、SKC 链接表现和流量分析使用。
- 订单明细事实和订单商品/SKC 明细事实暂不合并，因为订单到商品/SKC 是一对多关系。

## 当前后续方向：团队试用、代码管理、API 化和云端迁移

### P1：BI 局域网试用（已完成并封存）

- 早期目标：先让同事在同一局域网访问当前 BI 门户。
- 当前状态：已被云端入口替代；本地 `8787` 服务和局域网入口已封存。
- 回滚时才重新启用本地服务和防火墙规则。

### P2：GitHub 管理代码

- 目标：把项目代码纳入 GitHub 私有仓库管理。
- 范围：提交代码、文档、配置模板和必要脚本；排除浏览器 profile、密钥、本地数据库、日志、输出文件、备份和大体积运行数据。
- 交付：完成本地 Git 仓库、首个提交、GitHub 私有仓库和远端推送。
- 验收：`git status` 干净；敏感文件和大文件未进入仓库；`.gitignore` 覆盖当前运行目录边界。

### P3：SHEIN 官方 API 单店试点

- 目标：用户先申请一个店的 API 后，只接入一个店，跑通完整链路。
- 范围：按官方文档完成鉴权、抓取、入仓、BI 刷新和飞书异常通知；旧浏览器抓取保留为对账和回退。
- 交付：单店 API 抓取脚本和适配层，能写入现有 PostgreSQL / BI 数据模型。
- 验收：同一店铺同一日期的 API 数据与原浏览器抓取数据完成对账，差异可解释；失败重试、限流和日志可用。

### P4：16 店 API 分批替换

- 目标：在单店试点稳定后，把 15 个店铺逐批从浏览器抓取切换为官方 API。
- 范围：多店凭证管理、批次迁移、调度改造、回退开关、关键指标对账。
- 交付：核心日销、订单、商品/SKC 等数据域默认由 API 获取；浏览器 profile 降级为登录、排障或临时回退工具。
- 验收：每批迁移后验证当日、昨日、当月关键指标；单店失败不污染其他店；BI 和飞书通知仍保持一致。

### P5：云端服务器迁移（进行中）

- 目标：把系统从本地电脑迁移到云端服务器长期运行。
- 当前状态：腾讯云服务器已部署，云端 BI 入口已启用 Basic Auth，本地 BI 已封存。
- 已完成：销售 WebAPI 云端刷新、BI Portal 生成、PostgreSQL/Metabase 底座、数据库自动备份、ET 同步、飞书日报、异常通知、RTV 完整复核、链接/业务域日更和 HL OpenAPI 双跑。
- 待完成：域名/HTTPS、异地备份、动作状态入库、SSH 从临时 `443` 迁到正式高位端口、链接/业务域纯 Node 零浏览器直连优化。
- 验收：云端真实 timer 连续稳定运行；备份可恢复；异常能告警；出现问题可回滚到本地或上一版。
