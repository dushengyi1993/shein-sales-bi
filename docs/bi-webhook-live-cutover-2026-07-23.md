## 结论

- 本次只切换 **19 个半托店铺** 的当天订单销售链路。
- `shein-bi-cloud-today.timer` 已删除；不再每小时全店轮询当天 WebAPI/OpenAPI。
- 订单 Webhook 到达后，系统只查询变化订单并写入 `fact.openapi_order_*`；数据库触发器在切换日之后同步正式 `fact.order_*` 和店铺日汇总。
- 在线 BI 通过 PostgreSQL `LISTEN/NOTIFY` + 登录后 SSE 收到变化，再同步读取轻量 `liveSalesToday`。该查询直接使用当天 `mart.profit_order_item` 的净额/毛额事实，生产实测约 `0.45s`，不会每来一单就重建两分钟的全量利润缓存。
- `03:00` 前一日 WebAPI 最终定稿继续保留，作为完整日收口与独立核对；商品、流量、链接、RTV、仓储费等慢变域仍按日更或各自专用任务运行。

- 全托 `shein-fm-sales-sync.timer` 属于 `/opt/shein-fm/current`，与本仓库半托链路相互独立。

## 数据新鲜度边界

- 实时：平台动态、订单变化、当天销售净额/毛额与首页销售排行。
- 定向刷新：用户已打开的订单/成交价 section 会在事件后后台更新；不会为了首页数字强制生成 14MB 全量订单数据。
- 日更：商品全量列表、链接表现、流量、RTV 会计事实、仓储费和最终利润缓存。
- Webhook 退货事件会立即进入平台动态并触发定向查询；正式售后会计事实仍由日更收口，未完成该切换前不能宣称“售后利润实时”。
