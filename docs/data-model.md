# 数据模型

## 1. 店铺配置表

一行代表一家店。用于新增/停用店铺、分组、profile 和产品统计开关。

关键字段：
- 店铺代号
- 店铺名称
- 分组
- 是否启用
- 商品统计启用
- ProfileKey
- 订单页入口
- 备注

## 2. 抓取日志表

一行代表一次任务执行。只用于排错和审计，不作为经营统计底座。

关键字段：
- 唯一键
- 抓取时间
- 目标日期
- 店铺代号
- 任务类型
- 状态
- 有效订单数
- 销售额SAR/RMB
- 错误摘要
- 证据摘要

## 3. 店铺日报事实表

一行代表某店某日的最终经营结果，是月表、日报和仪表盘的数据底座。

唯一键：`YYYY-MM-DD__店铺代号`

当前已验证 SHEIN 抓取口径：
- 日期筛选按订单创建时间。
- 订单列表接口：`/gsp/orderPlus/listOrder`。
- 商品明细接口：`/gsp/orderPlus/listOrderItem`。
- 销售额 SAR：商品明细 `groupList[].goodsList[].currencyPrice` 求和。
- 有效订单数：至少一条商品明细 `currencyPrice > 0` 的订单数。

关键字段：
- 日期
- 店铺代号
- 店铺名称
- 分组
- 有效订单数
- 销售额SAR
- 销售额RMB
- 数据状态
- 抓取时间
- 数据来源
- 备注

## 4. 月度日销展示表

每月一张宽表，例如 `月度日销-2026-04`。它是展示层，可由事实表重建，不作为唯一真相来源。

行结构参考 3 月手工表：
- DSY 10 店
- DSY 小计 SAR / RMB
- LGM 5 店
- LGM 小计 SAR / RMB
- 总计 SAR / RMB
- 预测全月 SAR / RMB
- 预测利润 RMB

列结构：
- 主体/店铺
- 合计
- 日均
- 1日 ~ 月末

## 5. 产品销量事实表

一行代表某店某日某货号销量。

唯一键：`YYYY-MM-DD__店铺代号__货号`

产品统计当前覆盖 DSY 与 LGM 共 15 店。

货号归一化：货号开头的中文/英文括号标注（如 `（待定）`、`（废）`、`(废)`）仅作为备注，统计时先剥离再归并。

## 6. 产品周/月销量宽表

产品周销、月销现在只保留宽表展示，不再维护旧的周/月窄表。

- `产品周销量-宽表`：一行一个产品，周一到周日为一周，周别放在列上。
- `产品月销量-宽表`：一行一个产品，自然月放在列上。
- 宽表由 `scripts/generate_compact_display_tables.mjs` 从本地抓取明细/产品日事实口径重算刷新。

旧表 `产品周销量`、`产品月销量` 已删除；如后续要做更复杂的跨周期分析，应优先从 `产品日销量事实` 重新聚合，不要恢复窄表作为日常展示依赖。

## 7. 年度汇总与当月/上月独立表

独立月度展示表只保留当月和上个月，方便人工查看：
- `月度日销-YYYY-MM`
- `产品日销量-YYYY-MM`

更早月份不继续保留独立展示表，统一进入年度汇总表：
- `月度日销-YYYY汇总`
- `产品日销量-YYYY汇总`

年度汇总表必须包含该年度所有已抓取月份，包括当月和上月。也就是说，独立月表只是“额外方便查看”，年度汇总表才是“全年完整口径”。

`scripts/generate_compact_display_tables.mjs` 默认 `recentMonths=2`。每月切换后，会自动把新的当月/上月作为保留集合，并把更早独立月表列入 `cleanupCandidates`；真正删除云端表仍需用户确认。

## 8. 订单/SKC 明细底座与看板边界

为后续退货、成本利润、SKC/链接表现、流量分析，底层抓取应尽量保留详细字段，包括订单号、订单 ID、店铺、分组、订单创建时间、货号、标准货号、SKC、SKU、规格、商品名、数量、金额、订单状态、履约状态、售后/退货相关字段等。

但看板不直接读取大明细表。当月主看板读取 `看板数据-MAIN-*`，上月看板读取 `看板数据-PREV-*` 这类轻量聚合表：

- `看板数据-MAIN-范围汇总`：一行一个范围（全部、DSY、LGM），用于核心指标和分组对比。顶部单值统计卡必须读取 `KPI*` 专用字段；这些字段只在“全部”行填真实值，DSY/LGM 行填 `0`，避免把 `全部 + DSY + LGM` 重复求和。
- `看板数据-MAIN-日趋势`：按日期和范围聚合，用于同时展示全部/DSY/LGM 趋势。
- `看板数据-MAIN-店铺排行`：全部 15 店完整榜单，按销售额或销量降序；排行标签只保留排名+店铺代号，分组通过颜色表达。
- `看板数据-MAIN-产品排行`：全部货号完整榜单，按销量/销售额降序；产品榜使用紫粉系，避免和全部/DSY/LGM 分组色混淆。
- `看板数据-MAIN-历史月销`：按月份和范围聚合，用于历史趋势。

旧的 `看板数据-DSY-*`、`看板数据-LGM-*`、`看板数据-ALL-*` 以及旧 Dashboard 已清理；正式保留当月主看板、上月看板与对应的 `MAIN/PREV` 轻量聚合表。

产品排行应从本地订单商品明细按 `normalizeGoodsSn` 重新聚合，避免 DSY/LGM 或旧报告中的同一标准货号重复出现。

看板顶部 `数据时间说明` 是飞书内部 `RICH_TEXT` 组件，不属于普通数据表字段模型。公开接口创建文本块时会完成 Markdown 到富文本的转换，但公开接口更新已存在文本块会把 Markdown 作为普通字符串保存；因此不能用公开接口更新该块。当前刷新脚本通过已登录飞书网页 profile 调用内部富文本保存链路更新时间，并带轻量重试；如果该步骤失败，只代表顶部时间块可能滞后，不代表 `MAIN/PREV` 看板数据源没有刷新。

看板和日报图统一使用同一套颜色规范：全部/合计=绿色系，`DSY`=蓝色系，`LGM`=橙色系，产品榜=紫粉系。

## 9. 定时刷新边界

定时同步不允许单个分组成功后就刷新看板。正确顺序是：

1. DSY 完成抓取、事实写入、产品日事实写入。
2. LGM 完成抓取、事实写入、产品日事实写入。
3. 两组都成功后，统一刷新月表、年度汇总、周/月宽表、当月主看板和上月看板。

任何上游失败都应停止派生刷新，避免看板出现一组新数据、一组旧数据。




## 2026-04-29 HL 时区复核结论

- HL 后台页面时区已确认正确；系统曾统计错误，是因为本地店铺配置里保留过猜测性的 `accountUtcOffsetHours=3`，导致抓取查询区间被额外换算成 `19:00~18:59`。
- 已删除 HL 特殊偏移配置，并回补 HL `2026-02-04` 至 `2026-04-29`。后续默认规则：除非用户明确确认某店后台日期口径不同，否则所有店按后台日期直接查询北京时间自然日，不做单店额外偏移。
- 受影响后处理：重刷对应月份的店铺月表、产品日事实、年度汇总、产品周/月宽表、订单/SKC 明细和看板，再运行逻辑体检。
- 飞书接口出现 `tls/x509/certificate/not open.feishu.cn` 这类证书/CDN 抖动时应自动重试，不能发布半新半旧数据。


## 2026-04-29 月表保留与上月看板策略
- 独立月度展示表只保留当月和上个月：例如当前为 2026-04 时，只保留 `月度日销-2026-04`、`月度日销-2026-03` 以及对应 `产品日销量-YYYY-MM`；更早月份进入年度汇总表。
- `generate_compact_display_tables.mjs` 默认 `recentMonths=2`，每月过完后会自动把新的当月/上月作为保留集合，并把更早独立月表列入 `cleanupCandidates`，删除仍需用户确认。
- 当前有两个 Dashboard：`SHEIN经营看板 v3-主看板`（当月滚动）和 `SHEIN经营看板 v3-上月`（上月完整）。上月看板使用 `看板数据-PREV-*` 五张轻量数据源，避免与当月 `看板数据-MAIN-*` 互相覆盖。
- 看板继续使用轻量聚合数据源，而不是直接读取订单/SKC 大明细表；这样更稳、更快，也避免 Dashboard 直接扫事实表时筛选和排序不稳定。优化方向是减少重复数据源和字段，但不要让看板直接读大明细表。
