# 实际库存与销售去化周期口径

更新时间：2026-05-06

## 1. 这个页面回答什么

`实际库存 / 去化` 页面用于把成本表里的批次发货信息，和 BI 仓库里的真实销售速度结合起来，回答四个问题：

1. 哪些货号已经到仓、还剩多少估算可售库存。
2. 哪些货号正在路上，是否能接住当前销售速度。
3. 哪些货号快断货、已经售罄或成本表缺到仓批次。
4. 哪些货号库存沉淀、去化过慢，需要清货或暂停补货。

这个页面不是 SHEIN 后台“展示库存”的替代品，而是根据采购/发货批次和销售事实推算出来的经营库存视角。

## 2. 数据来源

### 成本表批次

正式成本表：`inputs/costs/成本.xlsx`。

关键字段：

- `型号` / `希音标准名`：用于归并到标准货号。
- `发货单号`：批次编号。
- `发货日期`：有值说明这批货已经发出。
- `到仓/派送日期`：有值说明这批货已经到仓或进入派送完成口径。
- `数量`：该批发货数量。
- `头程运输费`：有值说明这批货的头程费用已经确认。
- `单台总成本（SAR）`：用于成本/利润；库存页主要使用数量和批次状态。

导入脚本：`scripts/import_product_costs.mjs`。脚本会把发货日期写入 `fact.product_cost_batch.shipped_date`，把到仓/派送日期写入 `fact.product_cost_batch.arrived_date`。

### 销售速度

销售扣减来自 BI 利润事实层的商品销量口径，库存去化使用“毛销量”扣减，而不是净成交销量。

原因：退货品不一定能马上二次销售，先按保守口径不加回库存，避免高估可售库存。

## 3. 批次状态判断

| 状态 | 判断规则 | 用途 |
| --- | --- | --- |
| 已到仓 | `数量 > 0`，且 `到仓/派送日期` 有值，且 `头程运输费` 有值 | 计入当前可售库存基数 |
| 在途/待录头程 | `数量 > 0`，有 `发货日期`，但缺 `到仓/派送日期` 或缺 `头程运输费` | 计入在途/待确认补货 |
| 未发/待确认 | `数量 > 0`，但没有 `发货日期` | 只作未来计划或数据待补，不计入在库 |
| 忽略 | 数量为空或无效 | 不参与库存计算 |

注意：成本利润的“完整批次”仍然要求头程费用完整；库存去化页则把有发货日期但没到仓/头程的批次作为在途承接看待。

## 4. 库存与去化计算

### 4.1 估算在库

按标准货号聚合：

```text
估算在库 = 已到仓批次数量 - 累计毛销量
```

结果小于 0 时显示为 0，同时把差额标记为“超卖/成本表缺批次”。

批次明细里使用 FIFO 逻辑估算每个到仓批次剩余量：先到仓的批次先被销售扣减。

### 4.2 在途承接

```text
含在途总供给 = 估算在库 + 在途/待确认数量
```

在途只说明这批货可能会补上，不代表今天已经能卖。

### 4.3 销售速度

当前默认速度为加权日销：

```text
加权日销 = 近 7 天毛销量 / 7 × 40% + 近 30 天毛销量 / 30 × 60%
```

这样既能反映最近加速，也不会被单日波动过度影响。

### 4.4 去化周期

```text
当前在库可卖天数 = 估算在库 / 加权日销
含在途可卖天数 = (估算在库 + 在途数量) / 加权日销
去化率 = 累计毛销量 / 已到仓批次数量
```

如果加权日销为 0，则可卖天数显示为 `∞` 或空，页面会把这类货号归到低动销/沉淀方向，而不是断货方向。

## 5. 风险标签

当前数据库视图 `mart.inventory_depletion_product_current` 会输出以下主要状态：

- `成本表缺到仓批次`：已经有销量，但成本表没有可用到仓批次；优先补成本表/批次信息。
- `在途未到仓`：有在途批次，但还没有到仓库存；适合跟物流或到仓。
- `未发/待确认`：成本表有数量但没有发货日期；适合补录或确认是否还要做。
- `等补货/在途承接`：当前在库已无，但有在途批次；需要看在途是否来得及。
- `已售罄/疑似缺货`：当前在库为 0 且没有在途承接。
- `14天内断货`：按当前速度 14 天内会卖完。
- `30天内需补货`：按当前速度 30 天内会卖完。
- `库存偏慢`：库存可卖天数过长或近 30 天没有销量。
- `健康`：当前库存和销售速度相对匹配。

## 6. 页面筛选口径

- 货号/SKC/品名筛选：影响页面展示的货号范围。
- 店铺/分组筛选：影响销售速度和销量对比，但不拆分物理库存。
- 原因：成本表目前只有总批次，没有“这批货分给哪个店”的分配数据。没有真实店铺库存分配前，不能把总库存硬拆到单店。

如果未来接入真实仓储系统或店铺库存分配表，可以把库存基数升级为 `货号 × 店铺/仓库` 粒度。

## 7. 已知限制

- 这是估算库存，不是仓库系统实盘。
- 退货暂不加回库存；这是保守口径，适合经营风险判断，但会低估可再次销售的库存。
- 如果历史销量早于成本表批次，可能出现“成本表缺到仓批次”或超卖提示，需要补历史批次。
- 如果成本表发货日期、到仓日期或头程费用未及时更新，页面会把批次放到在途或待确认。
- 当前不按店铺拆库存，店铺筛选只改变销售速度，不改变全局库存基数。
