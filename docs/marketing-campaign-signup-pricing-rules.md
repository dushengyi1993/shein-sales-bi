# SHEIN 营销活动报名价格规则

## 适用范围

- 适用于 SHEIN 商家后台“营销活动报名”里的活动填报。
- 自动化只负责：
  - 勾选商品
  - 填写 `提报的活动价格`
  - 填写 `提报的活动降幅`
  - 滚动复核
- 自动化 **不得点击** 最终 `提交报名`；最终提交必须由用户在可见前端人工审核后点击。
- 页面里 `提报的活动价格（实际生效参考此列）` 优先级最高；`提报的活动降幅` 主要用于配合平台校验。

## 货号归并前置规则

- 报价前必须先做货号归并，统一使用：
  - `config/product_catalog.json`
  - `config/product_aliases.json`
  - `lib/product_sku_normalizer.mjs`
- 典型归并：
  - `TXSM-505A电动缝纫机` / `SM-505A电动缝纫机` -> 同款
  - `SK-7025绞肉机` / `SK-7025A绞肉机` -> 同款
  - `便携式咖啡机` / `KF-JN-02便携咖啡机` -> 同款
  - `185` -> `SK-185台式榨汁机`
  - `03012` -> `SK-03012台式榨汁机`
  - `03038` / `制冰机` -> `SK-03038制冰机`

## 报价优先级

1. 本期用户确认表 / 备注生成的逐店铺 + 活动 + SKC 覆盖价（row-level override）
2. 用户指定固定价
3. 用户指定利润率
4. 新品保护价
5. 库存沉淀 / 清货候选价
6. 默认利润率规则
7. 平台活动强制档位 / `VIP档` 最低降幅 / 页面回写结果复核（作为最终硬约束记录）

说明：用户在审核表 `修改意见/备注` 中给出的本期要求，只在转换成 `marketing-price-overrides-YYYY-MM-DD-approved.json` 后作为本批次逐行覆盖价执行；除非用户明确要求“同步进长期规则”，不要直接改写上方全局固定价 / 利润率规则。

## 二、用户指定利润率规则

> 这些货号先按指定利润率反推，再对“目标利润率”做小幅随机浮动：
>
> - 下浮 `2` 个百分点
> - 上浮 `1` 个百分点
> - 例如：
>   - `30%` -> 随机落在 `28% ~ 31%`
>   - `25%` -> 随机落在 `23% ~ 26%`
>   - `15%` 清货底线不再下浮到 15% 以下；若平台折扣继续压价，则必须单独复核。

公式：

`活动目标价 = 单台总成本（SAR） / (1 - 实际使用利润率)`

## 三、默认利润率规则

- 除上述固定价 / 指定利润率货号外，其余货号默认按 `30%` 利润率反推。
- 默认利润率也允许小幅随机浮动：`28% ~ 31%`。

## 三点一、新品保护价规则

- 刚到仓不久、且全店/多店上架不足约 `30` 天的新品，不按库存沉淀清货价处理。
- 本轮新增保护：这类新品按各店不同的 `23% ~ 26%` 目标利润率反推活动价，硬底线为 `20%`。
- 若货号同时命中上方“固定价”或“用户指定利润率”规则，必须优先执行用户指定规则；新品保护价 / 清货候选价不得覆盖用户点名规则。
- 若活动页存在 `VIP档`，必须优先满足 `VIP档` 的平台最低降幅；但填报后仍要复核是否明显低于 `20%` 利润率。
- 当前保护价明细输出到 `outputs/reports/marketing-new-arrival-protected-prices-2026-05-12.md`，本期覆盖文件为 `outputs/reports/marketing-price-overrides-2026-05-12.json`。

## 三点二、库存沉淀 / 清货候选规则

- 若商品已有在仓剩余库存，且库存去化周期 `> 6` 个月，按 `15%` 利润率报。
- 若商品已有在仓剩余库存，且库存去化周期 `> 3` 个月且 `<= 6` 个月，按 `23% ~ 27%` 利润率随机报，每个店铺可有差异。
- `15%` 是自动填报硬底线；低于 `15%` 的价格不自动填，除非用户单独点名允许。

## 四、成本来源规则

- 成本来源以当前正式成本链路为准：
  - 正式成本文件：`inputs/costs/成本.xlsx`
  - 营销活动成本映射：`tmp/mbrs/marketing-cost-map.json`
  - 营销活动成本映射生成脚本：`scripts/marketing/build_marketing_cost_map.py`
  - BI 导入脚本：`scripts/import_product_costs.mjs`
- 若货号缺完整成本，自动化不得擅自猜价，必须保留给用户确认。
- 对于缺“头程运输费金额”的批次：
  - BI 会保留批次记录
  - 但不参与完整单位成本均摊
  - 营销活动成本映射也默认跳过这类不完整批次

## 五、平台折扣与页面回写

- 若平台最低折扣要求更严格，则以平台允许的最高活动价为准。
- 计算方式：

`平台允许最高活动价 = 当前价格 × (1 - 最低折扣要求)`

- 若自动算出的目标价高于平台允许上限，则强制压到平台上限。
- 页面若因整数折扣、平台规则或前端联动而回写活动价：
  - 以页面最终实际显示值为准
  - 但必须记录“脚本目标价 / 页面实际价 / 实际降幅”

## 六、填写与复核要求

- 报名前若用户要求先审核标准，应先导出“按标准货号一行”的审核表，而不是 700+ 行执行明细：
  - 明细采集：`node scripts/marketing/export_dsy_marketing_standards.mjs --stores DL,DX,FY,LQ,NM,HL,JY,ZL,TS,MZ --all-open`
  - 审核交付表：`outputs/reports/marketing-standards-by-sku-YYYY-MM-DD.csv` / `.md`；如需用户直接填写备注，可另存为 `.xlsx`。
  - 用户填写 `修改意见/备注` 后，再转换成本期逐行覆盖价文件 `outputs/reports/marketing-price-overrides-YYYY-MM-DD-approved.json`。
- 活动范围必须按用户口径执行：
  - `--all-open` = 扫描全部未截止可报名活动。
  - 默认排除优惠券活动；只有用户明确要求才使用 `--include-coupon`。
  - 不要把“全部活动”误解成“两天内截止活动”。
- 活动列表必须分页全量读取 `get_activity_list?page_size=100`，不能只读第一页 / 前 30 条；否则会漏掉分页后的活动。
- 进入“选择商品”页后，必须先把右下角每页条数改为 `500 条/页`，再点击全选；不能在默认 `20 条/页` 下直接全选，否则会漏选第 21 个及之后的商品。
- 即使已切到 `500 条/页`，SHEIN 商品表格仍可能使用前端虚拟滚动，DOM 里只挂载可见行；标准导出必须优先使用 `query_supplier_goods_list_v2?page_size=500` 接口全量取商品，并核对接口返回 `total` 与行数一致。
- 全选后必须用页面上的 `总计 N 个` 与 `已选商品 N 个` 做一致性检查；不一致时不得进入下一步。
- 当前自动化执行入口为 `scripts/marketing/dsy_marketing_deadline_fill.mjs`；该脚本属于营销活动半自动操作入口，不是 Windows 计划任务。
- 脚本只允许完成勾选商品、填写活动价/降幅和复核；不得点击最终 `提交报名`，最终提交必须由用户在可见前端人工确认。
- 重扫漏报或用户质疑漏报时，不要只处理上一次报错活动；必须逐店重新扫描 DSY 店铺（含 `MZ`，除非用户明确排除）在时间窗内仍可报名的活动，发现新增抓入商品就补填。
- 若本期已生成价格覆盖表，执行时必须带 `--price-overrides outputs/reports/marketing-price-overrides-YYYY-MM-DD.json`，否则新品保护价、清货底线和本期用户确认价不会全部生效。
- 若本期价格覆盖表包含 `storeKey + activityId + skc`，它必须作为最高优先级逐行覆盖价执行，不能被全局固定价或利润率规则覆盖。
- `SK-13034` 这类用户明确允许“默认最低折扣先填”的缺成本例外，执行时用 `--min-discount-fallback SK-13034`，不得扩展到其它缺成本货号。
- 填报完成后，只保留用户需要人工提交的活动编辑页；关闭活动列表页、中间页和无需提交的店铺窗口，避免前台开一堆页面影响复核。
- 建议填写顺序：
  1. 先填 `提报的活动降幅`
  2. 再填 `提报的活动价格`
  3. 对固定价货号，如页面容易回写，可再次回写活动价确认
- 填完后必须滚动全表复核：
  - 所有已选商品都有活动价
  - 所有已选商品都有降幅
  - 无空值
  - 无明显超低价
  - 无平台校验错误
